# 独立审计记录

审计日期：2026-07-10

## 范围

审计覆盖 14 个浏览器脚本、核心规则与 AI、HumanAgent 交互状态、动画/音效、资源脚本、测试和 README。检查方法包括逐模块阅读、语法/数据结构校验、固定场景反例、牌数守恒随机对战和现有 UI 测试可运行性检查。

## 本轮修复

### 严重：状态与规则正确性

- 统一卡牌移动事件；获得、使用、装备、替换和判定区移动现在都会准确触发失牌区域事件。
- 修复虚拟延时锦囊容器与实体子牌同时残留导致的牌重复。
- 防止正在结算的锦囊被弃牌堆立即重洗并在自身效果中摸回。
- 增加 Agent 决策规范化和出牌动作二次校验，拒绝越权卡牌、重复/非法目标和伪造费用。
- 将判定拆分为改判与最终结果两个时序，使【天妒】取得改判后的最终牌。
- 【闪电】移交时跳过已有闪电的角色。
- 【寒冰剑】不再以“弃 0 张牌”替代伤害。
- 【贯石斧】可正确选择手牌和装备区的两张牌作为费用。
- 【雌雄双股剑】改由目标选择弃牌或令来源摸牌。
- 伤害被取消时不再错误触发【麒麟弓】。
- 【铁索连环】允许以自己为目标；修复重铸标记在选项层丢失、UI 两种用法互相覆盖的问题。
- 【结姻】在使用者满体力、男性目标受伤时仍可发动。
- 武圣、奇袭、国色、急救等“牌”转换支持手牌或装备区；倾国仍按描述仅使用手牌。
- 洛神改用统一判定流程，支持改判并允许停止继续判定。

### 高：UI 与异步稳定性

- 对手面板缓存签名加入可选/已选目标、当前回合、连环、翻面和身份公开状态，避免目标不可点或显示不刷新。
- 装备区卡牌可在制衡、流离、贯石斧和转换技中被实际选择，并有明确选中样式。
- 修复交互状态机达到最大选牌数后仍继续追加的问题。
- 动画队列支持多个等待者；动画异常不再永久卡住队列；清空队列会释放未执行任务。
- 修复救援动画字段名不一致。
- 启动参数会校验节奏范围，重复点击开始按钮不会创建两局并发游戏，异步启动错误不再成为未处理拒绝。

### 中：可维护性与诊断

- Game 构造、setup、发牌、start 和武将分配增加前置条件与重复调用保护。
- 恢复体力事件记录实际恢复量，而非请求量。
- 修复 AI 判断攻击来源敌友时参数方向反转。
- 新增结构校验、分层 npm 脚本、架构文档、测试说明和忽略规则。

## 当前验证结果

- `npm run check`：通过；14 个脚本、27 名武将、130 张牌、24 张立绘映射有效。
- `node test/unit.js`：75/75 通过。
- `npm test`：通过；默认 60 局 8 人对战无异常、无牌重复/丢失、均正常结束。
- `npm run test:stress`：通过；500 局、0 异常、0 牌数问题、0 未结束对局。
- 历史问题 seed `427627`：单独回归通过。
- 浏览器 UI：本轮环境缺少 Python Playwright，且内置浏览器禁止访问本地 `file://` 页面，因此未能在本轮重新执行。UI 源码修复已完成，但不能据此声称真实浏览器链路已复验。

## 保留的产品取舍

- 无中途存档/读档。
- 以项目内技能描述为准，部分技能是适合单机的简化实现，不等同于某一官方完整卡池。
- 经典脚本顺序加载是“直接双击离线运行”的有意约束；若未来转为模块/构建系统，应作为单独迁移，不与规则改动混在一起。

## 质量结论

已修复本轮能复现或由代码路径确定的缺陷，并显著收紧状态边界。任何非平凡软件都不能诚实地证明“绝对无 bug”；当前可给出的结论是：核心规则、已列反例和 500 局压力模拟均通过，浏览器 UI 仍需在安装 Playwright 的环境中完成最后一轮真实点击验收。
