# 风云弈策 · 汉末牌局

原创表达、纯前端、离线可玩的汉末题材隐藏阵营策略卡牌游戏。

## 开始游戏

直接打开根目录的 `index.html`。这是完整独立的游戏文件，已经内嵌规则、界面、程序化音效、24 张开放许可历史画像和逐项许可账本。

无需安装、服务器或网络；将三个仓库文件上传 GitHub 后也可以直接启用 GitHub Pages。牌局会在阶段和玩家行动事务边界自动保存，刷新或关闭后可以继续。

大厅可直接输入结算页分享的挑战码。挑战码固定参战人数、随机种子、玩家座位、身份、武将、起手牌和剩余牌堆，让不同玩家能够在同一个 HTML 中重玩相同初始局面。通过 GitHub Pages 等 HTTP/HTTPS 地址游玩时，结算页还会生成可直接打开的挑战链接；本地文件模式只显示挑战码，绝不会把电脑文件路径写入分享内容。

大厅也支持导出和导入个人存档码，用于在不同设备、浏览器、本地文件和 GitHub Pages 之间迁移未完牌局。存档码包含全部隐藏身份、手牌与牌序，只应由原玩家自己保管；需要公开分享时请使用不包含进行中隐藏状态的挑战码。

## 本轮十项实质改进

1. **目标与首局认知负担**：个人密令持续说明当前身份、准确胜利条件和公开进度；首次开局只讲三件必须知道的事，完整策略指南仍可从顶栏或 `?` 随时查看。
2. **位置、距离与目标预判**：中央座次按真实环形距离显示每名角色、当前行动者、下一位与随后行动者、攻击范围和坐骑修正；翻面角色会直接标出下一回合将跳过。选牌后先预览合法目标及距离公式，不再靠记忆和目测。
3. **卡牌可用性与动作语义**：灰置手牌直接解释次数、距离、目标、阶段或响应限制；卡面以基本、计策、装备三种稳定视觉家族区分，并保留具体子类与读屏名称。
4. **选择边界与防误触**：选牌、选目标和确认形成结构化步骤；显式支持“不选择并继续”，不会把 0～N 错当强制选择；确认按钮复述行动者、动作、目标和公开效果。
5. **速度、暂停与统一时间线**：慢速、标准、快速和瞬时四档覆盖电脑思考与全部演出；玩家可在下一个安全边界暂停、恢复或跳过，旧通知和已取消指南不会在稍后反跳界面。
6. **事件清晰度与关系追踪**：中文战报升级为结构化事件；每名角色头顶保留最近五次互动，行动者、方向、目标、牌、技能、数值和时点均可点击追溯。列阵与号令额外区分技能拥有者、实际出牌者、受益者和对手，不再把援助牌记到被保护者名下。
7. **战斗因果与视听反馈**：伤害属性、连锁、防具抵挡、连续响应、盟友代援、驳计奇偶、技能、治疗、濒危、救援和阵亡都有独立形状、文字、连线、闪烁及程序化短音；阵亡会指向真实击破者而非受害者。
8. **手机、键盘与低动态体验**：窄屏顶栏和行动按钮采用横向轨道，焦点只在对象真正出屏时跟随；方向键、数字键、Enter、Escape 与触屏长按走同一状态模型，并完整响应系统减少动态效果。
9. **电脑隐藏信息公平**：电脑只允许读取自己的身份、公开盟主席位、公开行动倾向及统一“已揭示身份”入口；26 项身份置换测试覆盖敌友、出牌、迎击、救援和驳计决策。
10. **复盘、恢复与分享闭环**：结算页从结构化公开事件生成关键转折与个人统计；可复制挑战码重玩同一开局，也可用带校验的个人存档码跨设备恢复，进行中隐藏状态不会混入公开挑战分享。

## 本次触屏、阅读与视觉十项优化

1. **真实 44 像素触控边界**：修复粗指针规则先统一放大、又被窄屏与横屏样式缩回 20～34 像素的问题；速度、工具、行动、座次、最新事件和手牌整理在最终媒体规则中保持至少 44 像素。
2. **五条互动改为一个可靠入口**：角色头顶仍显示最近五条摘要，但不再制造五个相邻且互相抢触摸的小按钮；整块互动区作为 44 像素入口打开角色关系页，再由其中五条完整的 44 像素事件行进入单条记录。
3. **整张角色卡承担检查兜底**：普通状态下轻触角色卡即可检查；选目标时短触选择、长按检查，滑动取消长按。距离、互动和详情等内层操作会阻止事件冒泡，不会误选目标。
4. **座次条成为触屏导航轨道**：每个席位具有 44 像素高度、横向滚动吸附和边界滚动隔离；八人局可稳定逐席浏览，不会因手指横滑带动整页。
5. **座次键盘采用漫游焦点**：Tab 只进入一次座次轨道，左右方向键移动唯一焦点；不再要求键盘玩家重复 Tab 七八次才能越过牌桌导航。
6. **目标选择暴露确定状态**：可选席位同步使用 `aria-pressed` 标明已选与未选，视觉选中态、读屏状态和引擎选择集合保持一致。
7. **行动顺序不再只靠边框颜色**：当前、下一位和随后分别显示“行动中／下一位／随后”文字徽标与实心点；翻面角色明确显示“下一位·将跳过”。
8. **事件类型不再只靠红绿紫色**：伤害、援助、技能、计策、阵亡和判定摘要分别增加“伤／援／技／策／亡／判”字标和左侧形状边界，高对比或色觉差异场景仍能辨认。
9. **最新事件入口可读可点**：中央事件条的单字圆点“详”改为明确的“详情”胶囊按钮，触屏保持 44 像素高度；行动者、动作、目标和数值仍在同一条结构化摘要中。
10. **高频自有控件优先放大**：本人技能、装备、判定牌和距离入口获得分层触控尺寸；所有按钮统一采用 `touch-action: manipulation`，减少双击延迟，同时保留横向滚动和缩放能力。

视觉层统一为水墨深绿、青铜和朱砂层级，新增卡牌类别色带、距离公式卡、重大事件舞台、结构化事件条、濒危/击破关系线及响应式牌桌。24 张画像全部改为 Wikimedia Commons 文件页当前标记为 Public domain 的历史图像；界面、图标、纹理和音效由本项目代码独立生成。

## 继续优化

- **多目标选择不再暗中换人**：选满后再点其他角色会保留原有目标，并明确提示“已达上限，先取消再更换”，不再静默踢掉最早选择。角色卡、本人头像和中央座次同步显示第 1／2／3 个目标；确认区保留目标姓名、选择顺序与“目标 N/M”配额，鼠标、触屏、键盘和读屏共用同一状态。
- **首局引导不会“未看先记”**：首次指南只有在弹窗真正成功建立后才写入已读状态；若统一时间线被取消、牌局已结束，或强制响应弹窗暂时拥有界面，引导不会被错误消耗，下次开局仍有机会显示。首局三步与完整指南也已同步最近互动的新路径：先打开角色关系页，再选择完整事件。
- **结算给出身份化胜负解释**：胜负页新增“取胜关键／败因复盘”视觉卡，根据身份目标、盟主存活、终局人数、独行客是否进入最终孤局及本人伤害、救援、击破统计，区分盟主提前阵亡、护卫失守、逐鹿集火失败、独行客过早阵亡、盟主过早退出和最终决胜失利；每种情况都提供与目标一致的下局建议。分享战果同步包含简短复盘标题。
- **阵亡后明确进入观战**：本人出局但牌局仍在继续时，顶栏下方会持续显示观战状态、存活人数和当前行动者，不再只在目标说明里留下模糊提示。可一键临时切换至极速并随时恢复阵亡前的精确倍率；临时加速不会写入个人偏好，也不会跳过响应、技能、伤害或胜负规则。若玩家原本已经使用极速，按钮会明确显示当前状态并保持不可重复触发，结算出现前观战提示会自动退出。
- **桌面开局页不再裁掉操作**：真实浏览器发现 1440×900 时开局卡片会被弹性压缩，而自身仍使用 `overflow:hidden`，导致开始按钮只露出一部分，导入、图鉴和存档状态完全不可达。品牌、设置卡片和页脚现在保持自然高度，由开局页统一承担垂直滚动；开始按钮在首屏完整显示，其余操作可沿同一页面继续滚动。
- **速度上下界只有一份真相**：引擎原本允许 `0.02–2.00`，设置滑杆却只允许 `0.05–1.80`，真实浏览器会把已保存的 `×0.02` 自动夹成 `×0.05`，造成顶部与设置页互相矛盾。两个入口现在覆盖同一范围；实测把滑杆设为 `0.02` 后，滑杆、读屏值和顶部自定义档均显示 `等待 ×0.02`。
- **手机工具不再只剩难猜单字**：窄屏原先通过 `display:none` 隐藏完整标签，使指南、图鉴、设置和战报在读屏树里成为无名称按钮。六个按钮现在均有稳定中文名称，40 像素横向轨道显示“暂停／指南／跳过／图鉴／设置／战报”；暂停后同步改为“继续”，仍保持 44 像素触控高度和横向滑动。
- **小屏横屏不再裁掉手牌**：667×375 复核发现，结构化选择摘要增长后，个人操作区的真实内容高度重新超出视口约 12.5 像素。极矮横屏现在隐藏与阶段轨道重复的三步小标签，并压缩个人区非交互留白；行动摘要、按钮和完整手牌继续保留，实际牌桌高度与视口一致。
- **结算边界彻底清理局中状态**：真实完整跑局发现结果弹层后方仍把已阵亡角色标为“行动中”，保留旧阶段高亮、电脑思考者和“正在布置牌局…”指令。胜负边界现在统一结束选择、思考、操作引导和座次队列，强制重绘缓存；顶部、阶段轨道、个人目标和指令区分别改为明确的“本局已结束”、最终胜方与个人胜负结果。
- **长复盘先让玩家看见胜负**：原先初始聚焦底部“再来一局”会让浏览器把长结算页直接滚到底部，胜负标题、身份解释和败因/取胜复盘都被跳过。现在结果标题作为不进入普通 Tab 顺序的程序化焦点锚点，弹层固定从 `scrollTop=0` 打开；真实浏览器确认第一眼呈现胜方、自己的结果和身份化复盘，随后 Tab 才进入底部操作。
- **挑战链接复制前可检查**：HTTP/HTTPS 结算页新增可展开的只读链接预览，玩家可在交给别人之前确认其中只有规范化后的 `challenge` 参数；界面明确列出不会包含速度、演示模式、牌局进度或隐藏身份。预览也兼作剪贴板权限受限时的手动复制入口，并已纳入结果弹层的键盘焦点循环。
- **连舟成为真实战术**：电脑会先解除自己或公开盟友的不利连舟，再结合自己手中的火焰、雷电进攻牌和场上公开连舟状态决定是否连接两名对手；只有纯猜测、没有后续收益时才优先重铸。判断只读取自己的手牌与公开局面，不接触暗置身份。
- **自己也是清晰目标**：连舟等允许选择自己的行动会直接把本人头像变为“可选自己／已选自己”按钮，显示公开效果预览并同步 `aria-pressed`；鼠标、触屏和键盘均可操作，离开选目标状态后头像恢复为武将详情入口。
- **有限牌堆不会形成摸牌活锁**：同一张实体牌在一个出牌阶段已经结算后，即使经洗牌再次回到手中，也要到下回合才能再次使用；不可用原因、检查点和恢复状态使用同一字段，避免多张摸牌计策在有限牌堆内无限互相抽取。
- **技能费用保持原子性**：主动技能校验不再先去重费用牌、却把含重复引用的原始数组交给执行层。调度、施惠以及诊疗等通用弃牌技能现在会直接拒绝同一实体牌被重复列入费用；无效动作不会弃牌、赠牌、摸牌、累计技能次数或产生部分治疗，避免异常 AI、损坏恢复帧或未来网络输入利用一张牌支付多次。
- **底层牌区移动也具备幂等性**：统一决策入口会把重复选择和越权牌规范化为请求允许的唯一集合；弃牌层进一步只处理并返回真正新进入弃牌堆的实体牌。重复弃置同一牌不会先从弃牌堆取出再放回，也不会再次生成战报、动画、`afterDiscard` 事件或失牌技能触发；虚拟牌中重复的子牌引用同样只移动一次。
- **独行客终局不再把自己当阵营**：电脑评估公开阵营强弱时显式排除自身，不会因自己的手牌与负向公开倾向被计入“逐鹿方”而在最终三人局停止进攻；曾经达到 1,500 回合的固定种子在当前策略下可于 54 回合确定结束。
- **公开倾向同屏**：每个角色显示“偏护盟／偏逐鹿／未明”，只由公开攻击、救援和已揭示身份计算；这是可质疑的局势线索，不是身份答案。
- **不可用不再等于无反馈**：出牌、响应、弃牌和选牌请求共用同一份合法选项表；桌面徽标、策略提示、读屏名称与卡牌详情展示一致的不可用原因，避免视觉状态和引擎规则各说各话。
- **确认前最后一眼**：卡牌、技能、费用、目标与公开效果不再挤成一行自然语言；结构化决策条使用固定的行动关系和完整读屏句，按钮同步变为“确认 · 使用征讨 → 赵云”或“确认 · 弃置 3 张牌”。
- **牌桌不会再像卡住**：统一注意力状态明确区分“轮到你”“等待你响应”“电脑决策”“规则结算”和“已暂停”。桌面阶段牌、手机紧凑状态条、指令区边框和读屏文字由同一模型驱动；响应发生在别人的回合时会同时显示当前行动者与阶段，玩家输入使用文字加高亮，减少动态效果偏好会关闭呼吸动画。
- **公平前提重做平衡**：所有隐藏席位以相同未知倾向和相同起手牌数量开局；只有身份公开的盟主获得人数补正。5–8 人桌进入盟主与独行客最终二人局时，独行客仅触发一次公开的孤局整备。
- **独行客目标改为公开状态机**：7–8 人局中，电脑独行客在最终二人局前不再主动把盟主列为敌人，并会救援盟主、反制对盟主的有害计策；6 人局仅在已经出现公开逐鹿倾向时保护盟主，3–5 人局保留更紧张的三方资源博弈。所有人数都只用公开死亡身份和公开身份配额判断“逐鹿者已全部出局”；若此时场上仍多于两人，独行客会通过结构化重大事件亮明身份，护军与独行客不再因历史倾向彼此误判，随后进入肃清与最终对决。
- **无限滚雪球改为可见资源**：张辽“疾取”由每回合无限发动改为每局最多三次；询问和结构化技能事件都会显示剩余次数。固定武将控制矩阵中，张辽作为八人局独行客的胜率由 61% 降至当前 15%，消除了远高于其他武将的单点异常；该矩阵是电脑策略回归证据，不代表真人牌局强度排名。
- **疾取不会劫持别人的摸牌阶段**：真实浏览器复核发现，技能触发器虽限制了整局次数，却遗漏“当前摸牌者必须是张辽”的归属校验，导致张辽可在其他角色摸牌时抢牌并让对方跳过摸牌。现在说明与执行都限定为“你的摸牌阶段”，跨玩家负向契约确认不会询问、消耗次数、转移手牌或修改他人的摸牌事件。
- **连续自损改为可控风险**：跨身份固定武将矩阵发现黄盖综合胜率低于各身份平均约 12 个百分点，电脑会在同一阶段连续发动“激策”把自己从 4 点压到 2 点。现在每个行动阶段最多发动一次，说明、可用选项和阶段标记使用同一边界；电脑在 3 点体力时只有手牌极少且持有疗伤资源才会冒险。30 局每身份复核中综合存活率由 26.7% 提升至 35.0%，八人独行客固定武将矩阵胜率由 5% 提升至 10%。
- **无成本受伤收益回归一牌一伤**：郭嘉“遗筹”原先每点伤害直接保留两张牌，在每角色×四身份各 100 局的定向矩阵中，盟主胜率达到 53%、独行客达到 26%。当前每点伤害补充一张牌，精确数量进入结构化技能事件；“收策”仍保留判定牌资源特色。相同矩阵中盟主降至 35%、独行客降至 14%，忠臣与反贼没有出现断崖式失效。
- **大型牌局藏锋脱身**：7–8 人局的独行客在常规救援全部失败、且场上仍多于两人时，可整局一次公开身份、恢复至 3 点体力并摸两张牌。使用状态进入检查点；触发事件直接记录恢复目标与摸牌数量，触发后所有电脑仅依据已经公开的身份将其视为敌对且非盟友，最近互动、关系卡和赛后关键转折都会记录这一节点。
- **保存状态可见**：顶栏显示等待保存、保存成功、恢复成功或保存失败；只在可序列化的回合、阶段、判定牌、玩家行动及回合结束事务边界写入存档，不会保存半结算牌区。
- **多标签页存档防冲突**：每局存档带稳定牌局标识和递增版本。若另一标签页保存了更新回合、建立了不同牌局或删除了存档，旧页面会停止自动保存并明确提示，不再覆盖或复活外部的新进度。
- **跨设备个人存档码**：持久事务边界可导出为带版本和完整性校验的 UTF-8 存档码；导出弹窗默认聚焦明确的复制按钮，不会让读屏直接朗读整段隐藏信息。导入默认聚焦粘贴区，会深度检查牌区引用、人数、对象键、执行帧、日志上限与完整恢复能力；玩家 ID 与座位必须唯一有序，身份配比、角色资料、体力与存活状态必须彼此一致，整副牌也必须精确匹配发布版 130 张实体牌。每张牌只能占据一个顶层牌区，虚拟牌必须拥有唯一、非嵌套且不同时裸露在其他牌区的实体子牌，可恢复帧也不得残留结算中牌。无效内容同步标记 `aria-invalid`，已有本地存档进入醒目的危险确认阶段且必须再次点击才会替换。
- **战报键盘隔离**：收起战报后其内部控件不可被 Tab 聚焦，按钮同步维护展开状态，Escape 可先收起战报。
- **不中断战报阅读**：玩家向上翻阅时，新事件不再强制滚到底部；未读计数可一键回到最新事件。战报提供明确的分类下拉、人物/牌/技能即时搜索和“匹配数 / 总数”反馈，组合条件也会继续作用于后续事件与存档恢复。
- **存档覆盖保护**：已有未完牌局时，新开会明确提供“继续、覆盖并新开、取消”；牌局内离开也区分保留边界存档和永久放弃。
- **危险操作必须二次明确**：覆盖自动存档与永久放弃本局都改为两次独立点击；第一次只进入醒目的待确认状态，并明确播报“尚未覆盖／尚未删除”，第二次才真正执行。待确认状态 8 秒后自动失效并恢复原按钮，关闭或切换弹窗也会解除；弹窗默认聚焦继续牌局或继续游戏，不会让 Enter 落到破坏性操作。若自定义确认模块异常，系统会保留原存档并引导重试或继续，不再退回割裂的浏览器原生确认框。
- **弹窗焦点与读屏语义闭环**：通用弹窗会关联标题和说明、隔离背景、循环 Tab 并在关闭后恢复原焦点；必选推演会隐藏实际不可用的关闭按钮，直接聚焦首个可操作项目。Escape 只由统一快捷键路由处理，避免一次按键触发多套关闭逻辑。
- **弹窗滚动与隐藏控件隔离**：长账本和详情弹窗会阻断触屏及滚轮的滚动链，滚动条出现时也不再让内容横向跳动；初始焦点和循环 Tab 会排除原生隐藏控件及隐藏容器中的后代，避免键盘焦点进入肉眼看不见的位置。
- **速度显示与实际倍率一致**：设置滑杆保留 0.01 粒度细调，持续显示“极速／快速／标准／慢速”和精确等待倍率；顶部速度选择器遇到链接或旧偏好带来的自定义值时会显示真实倍率，不再用最接近的预设名称掩盖实际状态。
- **设置状态完整可读**：文字大小、对比度、音效、背景音乐和音量全部使用关联的原生标签或明确的按钮状态；音量同步展示精确百分比，开关同时更新文字、`aria-pressed` 与读屏名称。速度和音量输出使用标准 `for` 属性，不依赖真实浏览器中的只读 DOM 属性。
- **结算可分享**：结算页锁定背景焦点、支持循环 Tab，并把标题与“你的阵营获胜／失败”结果同时关联给读屏；长复盘会阻断滚动链并稳定滚动条布局。可一键复制不含隐藏过程信息的战果摘要。
- **推演可达性**：推演牌改为真实按钮，提供选中状态和完整读屏标签，不再只支持鼠标。
- **快捷键可发现**：当前可用手牌直接显示 1–9 键位并写入读屏标签；速度选项改为与真实等待效果一致的定性描述。
- **矮屏横屏布局**：针对手机横屏和低高度窗口压缩牌桌层级，保住牌局指令、操作按钮与手牌区。
- **触屏命中区**：触屏设备上的主要按钮使用不小于 44 像素的操作高度；角色头顶的五条密集摘要合并为一个 44 像素互动入口，完整事件仍在详情页逐条可点。
- **跨存档完整复盘**：伤害、承伤、救治、受治、救援和击破改由引擎持续累计并写入检查点，刷新恢复后结算统计不会因战报截断而丢失。
- **可序列化规则执行状态机**：检查点升级为第 4 版，顶层异步流程不再依赖无法恢复的 Promise 调用栈；阶段开始、每张延时判定牌、玩家每次出牌选择及回合结束触发前都会提交无半结算牌的事务快照。中断后回滚当前未完成动作并从显式执行帧继续，不重复当前角色的回合开始或已经完成的结束阶段。
- **旧存档平滑迁移**：第 4 版仍按顺序读取第 3、2 版存档；损坏的新版本不会遮蔽可恢复的旧备份。第 2 版只能从最近 200 条结构化战报还原的统计会明确标注为不完整，避免把估算值伪装成完整记录。
- **后台生命周期管理**：切换标签页或页面进入后台时暂停电脑决策节奏、动画队列与程序化音频；电脑思考改为只累计真正可见的前台时间，返回页面后从剩余时长继续，不会立刻跳出已经在后台倒完计时的动作。`pagehide/pageshow` 也覆盖浏览器返回缓存路径，避免系统切页后恢复陈旧动画。
- **系统减少动态效果**：尊重操作系统的减少动态效果偏好，不再只关闭 CSS 动画后继续空等完整演出；切换偏好时也会安全释放正在运行的演出队列。
- **重大转折独立舞台**：藏锋脱身和最终孤局不再淹没在连续回血、摸牌动画中；统一舞台先呈现“身份公开／最终决胜”的人物、印记与规则后果，并接入同一条可取消时间线。速度调整、跳过动画和系统减少动态效果都会同步生效；视觉舞台固定从无障碍树隔离，读屏只使用唯一的即时高优先级播报，不再重复朗读。
- **战斗视觉锚点不会飞错**：角色卡和中央座次条都带座位编号，但受伤闪烁、飘字、目标光环、连线与震动不再使用全页面模糊查找。玩家自己的效果固定落在完整个人区域，对手效果只在对手轨道内定位，中央座次摘要不会再误收大型战斗反馈。
- **元素伤害不再只靠颜色分辨**：普通、火焰、雷电与连锁传导分别使用“伤／火／雷／连锁”浮字、数值、实线或虚线纹理和不同火花形状；快速模式下仍能直接看出属性与传导来源。玩家个人区域补上独立的受伤和治疗闪烁，不再只有对手角色卡产生反馈。
- **防具抵挡不再像结算丢失**：玄铁盾和藤编甲抵挡征讨、边患或箭雨时统一发出结构化防御事件，以“挡”字、金属／编织盾牌轮廓、明确防具名、独立闪烁与专属短音说明攻击为何没有扣血；破甲效果不会误播抵挡。盾牌、纹理与音效全部由 CSS 和 Web Audio 生成，不新增第三方素材或许可义务。
- **成功响应不再静默消失**：征讨迎击、边患应战、箭雨迎击和驳计统一记录响应者、来袭者、响应牌与被化解的牌，并分别使用“避／应／驳”文字、圆环／菱形／印记轮廓、明确结果浮字和程序化短音。需要连续两次迎击时，第一张会显示“1/2、仍需一次”的点状进度印记，只有第二张完成后才显示“2/2、化解”；中途失败的战报和事件详情会明确标为“尚未完成”，不再提前宣告成功。多层驳计按真实奇偶链逐次显示“第 1 次·计策失效／第 2 次·计策恢复／第 3 次·再次失效”，恢复时切换为独立的“复”字圆印，绝不会把反驳驳计误写成继续取消原计策。征讨迎击不再借用缺少目标语义的普通出牌动画；从未被调用且会让所有群体目标误显受击的旧震动动画已经删除。
- **技能发动不再只藏在战报里**：31 个装备触发、主动技能与被动技能事件全部经过可等待的统一技能边界；发动者显示原创技能名、首字印记、紫色闪烁和程序化短音，有目标技能用独立虚线从发动者连接到每个目标，无目标技能使用自结算形状。技能演出会按规则顺序等待，并继续响应速度、暂停、跳过和系统减少动态效果，不会与后续伤害、摸牌或恢复动画并发错位。
- **恢复与救援不再丢失来源**：普通自疗、群体同袍、诊疗、合援、濒危救援、同舟加成、藏锋脱身和孤局整备都把真实来源、目标、原因及封顶后的实际恢复量传入统一事件与动画。别人施救时先在施救者身上显示“救援 → 目标”，牌飞行只表达“谁出手”；实际结算再从来源向获救者绘制绿色关系线并显示“救援／诊疗／同袍 +N”。自疗与无外部来源的整备不伪造关系线，避免把出牌动作、治疗来源和最终恢复量混成同一个绿色数字。
- **同舟真正增加救援量**：修复基础疗伤必须先把盟主恢复到正体力才触发同舟的问题。吴营伙伴在自己回合外救治 −1 体力的盟主时，一张疗伤现在会依次恢复 1 点并由同舟追加 1 点，使其正确回到 1；更深的负体力也会在每次实际疗伤后结算加成，而不是中途漏掉。技能战报同步使用原创名称“同舟”，不再误写成泛化的“救援”。
- **列阵与号令不再冒名响应**：联动响应现在把技能拥有者、实际提供迎击／征讨的盟友、获得效果的角色及来袭者分别写入结构化字段。最近互动会显示“代迎／代讨”，事件详情明确“替谁响应”，视觉反馈从实际出牌者连向受益者并在受益者处显示“援”；技能事件归回真正拥有列阵或号令的角色，盟友牌只消耗一次。
- **号令征讨保留真实牌义**：偃月长刀追击不再在号令没有直接 `card` 字段时复用上一张征讨，避免第二击凭空继承旧牌的火焰、雷电、花色或实体引用；借锋也不再把盟友提供的火雷征讨降成中性普通征讨。统一响应牌解析会沿联动链取得实际提供牌，只有阵图等确实没有实体牌的响应才生成中性虚拟牌；藤编甲的免疫和火焰增伤因此以第二张真实牌为准。
- **响应攻击不会在结算中途洗回**：偃月追击与借锋产生的征讨现在和普通出牌一样进入实体牌结算边界。即使牌堆耗尽、伤害后先触发遗筹摸牌，盟友提供的征讨也不会提前混回牌堆或被再次摸走；后续承势仍能从弃牌区取得真实伤害牌。嵌套攻击结束后保护会在 `finally` 中释放，手牌、牌堆和弃牌堆合计始终只有一个实体引用。
- **夺辎会还原转化前的实体牌**：流芳把方块牌转为宴安放入判定区后，夺辎不再把虚拟宴安容器永久塞进获得者手牌。统一获得牌接口会先移除判定区容器，再展开并获得原方块实体牌；这一对应关系会完整写入检查点，刷新恢复后再夺辎仍取得同一张原牌。破阵弃置、雷暴转移、判定结算和阵亡清理继续维持各自正确语义。玩家不会凭空得到一张可以再次当宴安使用的虚拟牌，实体牌也不会同时出现在手牌、牌堆或弃牌堆。
- **存档结构必须自洽**：个人存档码的完整性校验用于发现传输损坏，不被当作来源认证或防作弊签名。恢复前会独立核对玩家拓扑、唯一盟主席位、公开身份、角色姓名与势力、生命值、阶段、公开阵营倾向、统计字段及胜负状态；卡牌则按内嵌的发布版牌组清单逐张核对名称、花色、点数、元素、类型、装备范围和总数。分享元数据也必须满足有限时间戳、安全牌局标识、整数修订号、受限写入者标识及已知挑战码版本，避免伪造的回退比较或租约信息进入界面。即使重新计算校验码，多个人占同一座位、凭空删牌、把迎击改成疗伤或把普通装备改成超远武器等明显破坏规则模型的内容仍会被拒绝；语义上仍然合法的改档无法在纯离线文件中鉴别，因此界面只建议导入自己导出的代码。
- **导入战报只作为受限文字与事件数据**：恢复前会逐条限制最近 200 条战报的文本长度、事件 ID、类别、时点、参与者、牌、技能、伤害属性和对象深度；重复事件、未知玩家、伪造 CSS 类名、嵌套载荷及不完整互动会在界面启动前被拒绝。角色详情也不再通过字符串拼接 HTML；即使战报文字长得像图片或脚本标签，战报、最近互动、事件详情与读屏标签都只把它当作普通文字。
- **导入前先比较、再确认**：粘贴存档码后的第一次点击只校验并展示“即将导入 / 本地现有”两份摘要，不会写入存储；没有旧存档时也必须第二次点击才导入。若同一牌局的导入回合不比本地更新，会额外提示可能回退进度；存在旧存档时确认按钮明确切换为危险替换状态。输入一旦变化，摘要、确认状态和读屏关联会立即复位，避免校验甲代码后误导入乙代码。
- **濒危到阵亡保留完整因果**：濒危舞台显示伤害来源、目标当前体力及“仍需 N 点恢复”，负体力不会再被模糊成一次救援即可解决；每位电脑考虑救援时会明确显示正在救谁和剩余需求。救援失败后，阵亡事件把真正的击破者记为行动者并保留关联牌、属性和原因，击破者与阵亡者分别看到“亡→目标／亡←来源”；雷击等无角色来源的阵亡明确写为“环境/系统”，不再伪装成死者自己导致阵亡。普通动态效果用朱砂关系线和双端反馈表达击破，减少动态效果模式仍保留完整的高优先级结果播报。
- **伤害事件保留完整因果**：结构化伤害记录新增关联牌、伤害属性、结算原因与是否来自连锁传导；最新事件条和详情会写“连锁传导伤害”“火焰／雷电伤害”，动画与战报共用同一份语义，不再分别猜测中文句子。
- **恢复与焦点韧性**：损坏的新版存档不再遮蔽仍可恢复的旧版备份；通用弹窗打开时会隔离大厅和牌桌，关闭后恢复原焦点及原有隔离状态。
- **分享失败仍可用**：剪贴板权限被拒绝时继续尝试兼容复制；若浏览器仍不允许，结算页会显示、选中并允许手动复制完整战果，不再只弹出不可选择的文字。
- **目标距离不中断**：进入选目标状态后继续保留距离和攻击范围徽标，“可选目标”标记移至角色卡另一侧，不再用状态标签覆盖关键战术信息。
- **距离计算不再靠猜**：角色左上角距离徽标升级为鼠标、触屏与键盘都可打开的原生按钮；详情按公开状态列出存活座次的正反两条路径、进攻坐骑、防御坐骑、技能修正、最低距离、最终距离和攻击范围，并单独给出反向距离。阵亡角色会从路径中移除，两个方向不再被误认为必然相同。
- **出牌前公开效果预览**：合法目标直接显示命中后的基础伤害、防具抵挡、火焰增伤、连环传播、可能致命或可操作区域牌数；只使用公开装备、体力、连环状态和玩家自己的强化，不读取目标响应牌或隐藏身份。
- **移动端边界保护**：长按手势被系统取消时同步清理计时器；刘海屏和横屏设备按四周安全区调整顶栏、牌桌与手牌控制区。
- **事件读屏去重**：完整战报仍可逐条浏览，但不再与中央关键事件提示重复自动播报，减少连续电脑行动造成的语音轰炸。
- **互动事件不再漏人**：迎击、装备防护、驳计、群体计策响应、延时判定、击破奖励与误伤惩罚均直接记录行动者、目标和牌/技能主题；角色最近五次互动不再依赖中文句子猜测参与者。
- **最近互动真正可追溯**：标签直接由结构化行动者、目标、牌、技能和数值生成；行动者看到“伤−1→孙尚香”，承受者看到“伤−1←关羽”，群体计策显示“边患→2人”，自我技能显示“承势·自身”。火攻征讨等长名称会保留可辨识主题并紧凑显示，不再只用“伤／策／技”让玩家逐条点开猜测。角色卡在手机上为五条互动保留三行空间；标签可被鼠标、触屏和键盘打开，点击会阻止穿透选中目标，并保留完整读屏名称。
- **角色卡不再按钮套按钮**：整张对手卡改为带快捷键说明的可聚焦角色组，内部最近互动、判定牌和武将详情保持各自的按钮语义；Enter 仍按上下文选择目标或查看武将，左右键仍切换角色，全局确认不会抢占操作。详情按钮移至右上角，手机端事件标签下移，避免两者重叠。
- **角色卡内部键盘操作真正隔离**：修复 Enter 在内部原生按钮上冒泡到整张角色卡的问题；查看距离、武将、装备、判定牌和最近事件时不会再意外选择目标，只有焦点直接位于角色卡本身时 Enter 才执行牌桌上下文操作。
- **高频入口改用原生控件**：我的武将头像、装备、判定牌、角色最近互动和完整战报条目由模拟按钮改为原生 `button`，不再自行复刻 Enter/空格行为；卡牌画布仍保留专用选择模型。触屏主要操作继续保持 44 像素命中区，高密度事件与状态标签单独维持紧凑布局，避免手机牌桌被原生化后撑高。
- **事件详情改为关系卡**：点击战报或角色互动后，先显示“行动者 → 动作 → 目标”，再列出中文类别、牌/技能、关联牌和带单位数值；不再向玩家暴露 `trick`、`respond` 等内部英文键。
- **最新事件改为关系条**：牌桌中央不再展示需要自行拆解的整句战报，而是直接呈现“行动者 → 行动【牌/技能】→ 目标”和独立数值；桌面与手机均保留最新一次关键互动，并可从“详”按钮进入同一份结构化证据。
- **可复现挑战码**：新牌局使用单一种子确定座位和全部随机初始条件；结算摘要自动附带挑战码，大厅输入后可复现身份、武将、起手牌与剩余牌堆。挑战版本会写入存档，旧版本牌局不会被错误标记为可复现。
- **挑战码输入即时闭环**：键入或粘贴完整代码后立即规范化并同步人数、武将、邀请卡和开始按钮，不再等待失焦；半成品保持中性提示且不会修改当前配置，完整错误会同时显示红色状态和 `aria-invalid`。Enter 完成校验后把焦点交给明确的“开始挑战”按钮，避免无提示直接开局。
- **动态焦点连续性**：手牌、对手卡和座次条因选择状态或回合推进而重绘时，会按牌 ID 或座位恢复到同一对象；不会再把键盘焦点无声丢回页面根部。
- **大型牌局回合不丢视野**：手机对手轨道溢出且新电脑行动者位于屏幕外时，会在下一帧将其带到中央；已完整可见、轮到自己、同回合重绘、正在选目标或键盘焦点停在其他角色时都不会移动。跟随任务进入可取消统一时间线并拒绝过期回合，系统减少动态效果开启时改为瞬时定位。
- **方向键牌桌导航**：聚焦手牌、对手或座次节点后可用左右方向键循环移动；座次条同步显示已选目标，不再只依赖远处角色卡的颜色变化。
- **行动顺序进入座次模型**：当前角色不再只靠光圈表达，座次条同时写出“行动中、下一位、随后”；下一位若处于翻面状态会明确显示“将跳过”，读屏名称同步说明规则后果。顺序由存活座次和引擎的顺时针方法生成，死亡席位会被跳过，跨越末席时正确回到首席，结算后不再显示误导性的下一回合。
- **按请求生成操作步骤**：操作引导只显示当前动作真正需要的环节；无目标牌不再伪造“选目标”，即时响应不再伪造“确认”，先选角色再选牌的技能会按真实顺序推进。
- **横屏阶段不断线**：低高度横屏隐藏完整阶段轨道时，顶栏仍持续显示当前武将与阶段；桌面阶段轨道和紧凑状态均使用武将名而非匿名座位名。
- **角色卡成为移动端统一检查入口**：窄屏或矮屏横屏即使隐藏角色头顶事件，轻触整张角色卡仍能在一个检查页看到“你到对方／对方到你”的双向距离、自己的攻击范围、连舟、翻面、存活、判定区、公开行动倾向和最近五条互动。进入选目标状态后，普通轻触仍然选择，静止长按只打开检查页并抑制合成点击；横向滑动会取消长按且不会误选，距离、事件和装备等内层按钮也不会触发父级手势。互动使用完整文字与 44 像素原生按钮，无需精准点中画像上的微型徽标。
- **快捷键不劫持焦点**：全局 Enter 只在页面空白上下文触发确认；聚焦取消按钮、卡牌、角色或座次节点时，保留该控件自己的 Enter 行为，避免“想取消却确认”和确认旧目标。
- **单文件启动自救**：最早执行的启动保护会捕获脚本错误和未处理异步失败，给分享接收者显示可理解的反馈，并恢复大厅按钮和原标签，不再留下永久灰掉的入口。
- **恢复失败不删档**：继续牌局若在反序列化或界面启动阶段失败，会回到可重试大厅并保留原存档；玩家仍可选择重试、明确删除或覆盖新开。
- **开局前检查存档能力**：大厅会实际执行一次无损读写探测并持续显示本地自动存档是否可用；受限隐私模式或禁止存储的 `file://` 环境仍可正常游玩，但会明确标为“仅本次会话”、禁用无法完成的导入入口，并停止回合级重复保存尝试。探测会恢复此前存在的同名值，不留下测试数据。
- **跳转链接跟随当前界面**：键盘用户在大厅使用跳转链接会进入开局设置，牌局启动后同一入口自动改为进入当前操作区；启动或恢复失败返回大厅时，目标、文字和焦点会一并恢复，不再跳向隐藏牌桌。
- **量化视觉可读性**：阶段轨道、操作步骤、手牌说明、牌堆、结算标签和大厅辅助文字改用统一的两级灰绿色令牌；关键组合以 4.5:1 为最低对比度门槛。
- **可持久化显示偏好**：大厅和牌局设置均可切换标准/大字与高对比显示；偏好即时应用并独立保存，不改变规则、牌局存档或分享码。高对比关键语义色实测均达到 7.5:1 以上。
- **状态不只靠颜色**：可选目标、已选牌、攻击范围、当前阶段和保存结果同时使用文字、边框或形状及无障碍状态，不要求玩家仅凭红绿差异判断。
- **手机手势不误出牌**：长按查看卡牌使用带 12 像素容差的独立状态模型，允许正常手指抖动；轻触、长按、横向滑动、多指取消和系统取消被明确区分，长按或滑动结束不会再合成一次出牌点击。
- **破甲结算完整一致**：破甲剑命中后会在直接伤害阶段继续忽略目标防具，不再错误地重新触发藤编甲火焰增伤；传导到其他连环角色的伤害仍按各自防具正常结算。
- **扩展层不再覆盖核心方法**：战报表达、首局引导、卡牌提示和局势导航改由 `onExperienceStart`、`decorateCard`、`renderExperience` 等显式钩子接入；结构审计会拒绝同名方法的后置静默替换，减少加载顺序和参数契约造成的隐蔽回归。
- **短暂界面状态不会被旧任务反跳**：连续通知使用递增版本隔离，先取消旧计时任务再写入新内容；旧通知的取消回调无法再把刚出现的新通知隐藏，取消当前任务仍会正确清理界面。首局指南进入独立 `guide` 时间线作用域，取消任务只取消、不再反向打开弹窗；回调执行前还会确认牌局仍存在且尚未结束，避免启动失败、重置或终局后弹出陈旧指南。
- **弹窗不会连带取消牌局操作**：弹窗内的 Escape 会在本层完成关闭并停止传播，不再继续触发全局取消；强制响应拥有弹窗期间，指南和其他次级详情不能覆盖未完成的规则请求。普通详情原位替换会保留最初的外部返回焦点、清除旧滚动位置；焦点意外逃出时，下一次 Tab 会立即收回到弹窗内。
- **模块作用域依赖可审计**：全部内嵌 JavaScript 模块增加未定义引用审查，浏览器提供的全局对象与项目私有符号分开分类；跨模块功能必须经 `SGS`、`UI` 等显式命名空间暴露，不再假定另一个闭包里的局部函数可见。同步移除无用途的局部变量与动画辅助函数，减少伪依赖。
- **UI 巨型模块拆解**：原本混合基础装配、牌桌渲染、玩家决策、赛后结算、电脑节奏和战报控件的 1,417 行界面闭包，当前分为 229 / 586 / 385 / 183 / 202 行五个职责模块；卡牌与角色的长按检查共用基础层中的可取消手势绑定，不在渲染层复制计时逻辑。共享 DOM 操作只经 `SGS.UIDom` 暴露；组件契约限制基础层不超过 250 行、任何界面组件不超过 650 行，并验证关键方法只能由指定模块拥有。
- **许可界面独立边界**：审计发现详情弹窗模块曾增长到 673 行，超过文档声明的 650 行上限，而旧边界测试没有覆盖它。开放资产账本与安全外链现拆为独立模块；当前许可账本模块 156 行，弹窗生命周期、设置与图鉴模块 569 行。角色关系检查视图归属于 266 行结构化互动模块，不再挤回弹窗生命周期；边界契约同步覆盖行数、方法所有权和加载顺序。
- **启动与存档职责分离**：原 894 行启动模块同时管理大厅、牌局装配、本地存储、并发租约和跨设备迁移。浏览器持久化现成为独立的 409 行服务，启动装配降至 546 行；牌局只通过 `BrowserPersistence` 查询能力、建立租约、保存、恢复和清理。真实 DOM 契约会模拟连续版本写入、其他标签页更新、冲突后禁止覆盖及永久清理，避免拆分只改变文件外观而损坏存档语义。
- **视觉层叠可审计**：原 1,034 行样式模块同时包含基础大厅、牌桌、现代主题、动画、响应式与安全区覆盖。现在保持原先后顺序拆为 590 行基础样式和 450 行体验样式；独立契约检查语法闭合、加载顺序、关键选择器归属、手机/横屏/触屏/减少动态效果覆盖，并禁止 `@import` 或网络图片依赖，防止以后用偶然的后置覆盖维持视觉。

- **卡牌管线按信任边界拆分**：原 1,229 行模块同时处理响应、驳计、合法选项、动作校验、征讨和全部计策效果。现拆为 287 行响应/驳计层、445 行合法行动/执行入口和 582 行效果结算层；契约锁定浏览器与模拟加载顺序、各方法唯一所有权，并逐段确认连舟重铸的显式动作路径、联动响应归属与实体牌防循环不会在模块间丢失。
- **技能按势力注册且拒绝静默覆盖**：原 663 行技能对象把四个势力与共享选牌辅助混在一起，技能重名会被 JavaScript 对象字面量静默覆盖。现在拆为 277 / 168 / 182 / 100 行的魏、蜀、吴、群四个模块，并由统一注册表校验 42 个技能的内部键、中文名称、说明、势力归属和重复定义；27 名武将引用的每个技能也必须存在且属于同一势力，浏览器与无界面测试都锁定为“注册表与四势力技能先于武将数据”。
